# TP4 decode 延迟分析与验证边界

分析日期：2026-09-29。本文记录本 PR 所依据的冻结源码验证结果。
本 PR 暂作审阅草稿，与最新 `main` 的并发路径仍有待整合冲突；下列结果
不代表完成冲突整合后的主线版本已经通过端到端验证。

## 工作负载与正式结果

- Intel Gaudi2，TP4×PP1，共四张卡；正常 Chat API、单活跃请求、greedy decode。
- 生产容量保持：1,048,576 context、8192 prefill token budget、32 request slots。
- 输入 16,384 tokens，输出 2,989 tokens（包含推理 token），自然遇到 EOS ID 1。
- 按既定协议仅一次无 profiler 正式请求；复用归档基线，没有重测基线。
- 输出 token IDs 与既定参考完全一致；该样本的事实、计算、依赖顺序和缺失信息检查通过。
  这是固定样本验证，不是广泛的模型质量评测。

| 正式指标 | 实测 |
|---|---:|
| 引擎 decode 平均延迟 | 16.563729 ms/token |
| Decode 速度 | 60.372880 tokens/s |
| Prefill | 26.072025 s |
| Prefill 速度 | 628.413031 tokens/s |
| 客户端 TTFT | 26.148276 s |
| 客户端完整请求 | 75.609623 s |

归档上一候选为 17.497869 ms/token，本组合降低 0.934141 ms（5.3386%）。
该对比不是相对当前 `main` 的同条件测速。100 tokens/s 的目标尚未达到。

**Prefill 存在未解释的计时差异：**后续带 profiler 的 prefill 为 16.601888 s，
与正式请求的 26.072025 s 不同。保留正式值，不用较快的 trace 值替换，也不宣称
已经证明该差异来自算子回退。

## 同一份四卡 trace 的可加总延迟账

全部 31 个完整周期均予保留，平均 17.021524 ms，中位 15.962057 ms，
最短 15.089962 ms，最长 33.218335 ms。没有按延迟挑选周期。
窗口覆盖绝对 token 位置 16514–16544。

计时边界是连续 worker token 提交之间的吞吐周期，含当前 token 的后段与下一 token
的前缀；它不是单个逻辑 token 的独立 forward 时间。以下不缩放到无 profiler 的正式速度。
同组先取区间并集，四卡对齐，跨功能组同时活动只计一次。

| 功能组或可见活动 | ms/token | 完整周期占比 |
|---|---:|---:|
| Attention / CSA2 | 5.829707 | 34.249% |
| MoE | 2.953686 | 17.353% |
| mHC 及其他辅助操作 | 3.736889 | 21.954% |
| 上述功能组跨组重叠，只计一次 | 1.295718 | 7.612% |
| 仅 DMA 搬运 | 0.914965 | 5.375% |
| 仅设备调度 / TPC null | 0.163204 | 0.959% |
| 四卡均无可见设备活动 | 2.127356 | 12.498% |
| 完整周期 | 17.021524 | 100% |

计算活动并集为 13.815999 ms；其补集为 3.205525 ms。上表按未舍入值核验闭合。
辅助组包括量化、Engram、输出头及尚未进一步归属的融合/张量操作，不能全部称为 mHC。
匿名排序仍按冻结分类保留在辅助组，不通过重新归类宣称 Attention 提速。

无可见活动按其发生时所处的 host 阶段定位：

| 空档位置 | ms/token |
|---|---:|
| 输入准备与 step 衔接 | 1.130051 |
| Compiled 分组入口内 | 0.991162 |
| 结果消费与状态提交入口内 | 0.006143 |
| 合计 | 2.127356 |

这是位置划分，不是 CPU、网络或同步的因果归因。0.006143 ms 不等于完整 token 回读耗时。
小于 10 微秒的空档累计 1.746050 ms/token，占全部空档 82.1%；最长单次共同空档
0.266326 ms。不存在连续 0.5 ms 以上的共同空档，但许多短空档仍会累积成长尾。
NIC 传输缺乏完整可见性，不能把共同空档全部归为可消除空闲或通信等待。

## Attention 瓶颈证据

每卡冻结 Attention 分类中的 MME 活动并集为 1.331–1.334 ms/token，
TPC 活动并集为 3.924–3.937 ms/token。两者可以重叠；活动时间不是 ALU 利用率。

| 局部链环节 | 每卡活动统计，ms/token |
|---|---:|
| Packed KV 解码及 K/V/mask 整理 | 约 0.926 |
| 对应 QK + PV 矩阵计算 | 约 0.130 |
| 索引 key 寻址与 FP4 解码 | 0.761–0.763 |
| 后续索引评分矩阵计算 | 0.052–0.053 |

这些是归档 kernel 行的局部活动统计，可能相互重叠；不能相加充当四卡 5.829707 ms
的分解，也不能直接从端到端延迟扣除。

源码与编译图支持以下判断：

- 索引 query/head weights 汇集到完整 32 个头后，各卡仍重复处理完整候选；共享 latent
  KV 的准备没有随 query head 的 TP 切分同比缩小。
- 索引 key 准备依次执行逻辑行读取、页表访问、packed 数据与 scale 读取、位拆解、缩放和
  BF16 写出。矩阵乘法前的数据准备是明确的优化对象。
- 当前索引解码的保守 `allRequired` 访问合同限制细粒度 TPC→MME 流水；源码记录了
  Synapse 对旧混合访问映射的限制。不能直接清掉标志，且尚未量化这项限制的独立延迟贡献。
- M=1 主要投影具有低权重复用特征；权重仅读取一次的等效速率约 1.66–1.92 TB/s。
  这个估计不计缓存、重复读取和其他引擎流量，不是实测 HBM 带宽或饱和率。

现有证据支持优先优化数据准备、重复工作与执行依赖；没有证明矩阵算力或 HBM 带宽已经用满。

## 本 PR 范围与后续工作

本 PR 纳入冻结服务版本的 TP4 拓扑、设备 token/Engram continuation、输入与位置准备、
MoE/scale 路径、mHC 处理、直接 packed KV gather、可见前缀裁剪，以及 trace 分析工具。
数值边界、原排序和候选发布语义继续保留。

逻辑 MLA/紧凑 offsets、有界 decoded-index mirror、local-query 复制和跨卡候选分块
不作为本 PR 的新默认路径。部分后续改动只有组件结果，不能计入这里的端到端成绩。
历史跨卡分块版本在真实消费链中变慢，后续必须改变通信/合并依赖，不能原样重试。
